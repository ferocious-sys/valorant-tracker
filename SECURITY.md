
# Security Policy

## Reporting a Vulnerability

The security of Valorant Tracker and its users is important.

If you discover a potential security vulnerability, please report it responsibly.

**Please do not publish unpatched vulnerability details in a public GitHub issue.**

### How to Report

1. Open the [Valorant Tracker Security Advisories page](https://github.com/ferocious-sys/valorant-tracker/security/advisories).
2. If private vulnerability reporting is enabled, use the option to report a vulnerability privately.
3. If private reporting is unavailable, contact the repository maintainer through GitHub to arrange a private reporting channel.

When reporting a vulnerability, include:

- A clear description of the potential issue.
- The affected version, commit, or component, if known.
- Steps to reproduce the issue, where safe and appropriate.
- The potential impact.
- Any suggested mitigation or fix.

Do not include passwords, access tokens, real user credentials, or other unrelated sensitive information.

### What to Expect

The maintainer will review the report and may request additional information.

Please understand that response times and fix timelines may vary. Do not assume a report has been received or resolved until you receive confirmation.

### Scope

Security reports may include issues involving:

- Unauthorized access to user data.
- Exposure of credentials or secrets.
- Authentication or authorization weaknesses.
- Vulnerabilities in application dependencies.
- Unsafe handling of user-provided data.
- Other reproducible security issues affecting the project.

This policy does not authorize testing against systems, accounts, or services that you do not own or have permission to assess.

### Supported Versions

The project has not established a formal supported-version policy in this document. Check the repository's releases and maintenance notes for information about the versions currently receiving updates.

Thank you for helping keep Valorant Tracker and its users safe.
